# Decision log

The decision log of HyprAero's design branch. Newest last. One line per decision: date, decision, reason. Read the relevant entries (grep for the topic) before changing a rule, and append new ones here. Decisions from before this branch existed are in the `bar` branch's `DECISIONS.md`.

- 2026-10-24 - HyprAero is one repository with a branch per module (`bar`, `notifications`, ...) and a landing page on `main`; the design (tokens, primitives, theme follower) and the Aero kit are the `design` branch, included in each module branch as a git submodule at `design/` (`branch = design`). It was cut out of the bar's history with `git subtree split --prefix=design`, so its files keep their history. Reason: owner's request: a module installs and runs on its own (`git clone -b <module> --recurse-submodules`) without the other modules' code or resources, the repository stays one, and the design is never copied. The rules every module shares (repository layout, Windows' assets, glass, identifiers) moved into this `AGENTS.md`, which each module's `CLAUDE.md` loads.
- 2026-10-24 - Files here import only Qt, Quickshell and this folder. `SystemTheme.qml` and `colorScheme.js` moved here from the bar's `services/`; `iconColor.js` moved here whole (only `IconColorReader` used it); the analog clock's `handAngles` moved out of the bar's `calendar.js` into `clockHands.js`, and the avatar's `initial` and `avatarIndex` out of the bar's `userInfo.js` into `avatar.js`, each with its tests. Reason: the branch must load in any module, which has no `services/` of the bar; the calendar and the user's folders stay the bar's logic.
- 2026-10-24 - `DragSource` is not part of the design; it goes back to the bar. Reason: it reads the bar's `Apps`, `Workspaces`, `Tray` and `BarDrag`. It came here on 2026-10-11 only to keep the bar and the start menu from importing each other, which a neutral folder in the bar also does.
- 2026-10-24 - `WindowsIcon` keeps reading `../resources/icons/`, which inside a module is the module's own folder. Reason: each module ships only the Windows icons it uses.
- 2026-10-24 - QML tests stand in for Quickshell's `Singleton` (now holding children), `Process` and `SplitParser`, and register the real `SystemTheme.qml` as a singleton in the fake `qs.design` qmldir. Reason: `Theme.qml` finds `SystemTheme` through its own folder, and Qt treats a `pragma Singleton` file found that way as a plain type unless a qmldir registered that file as a singleton (import trace: `TYPE/URL`; every test warned `Unable to assign [undefined] to bool` at `Theme.qml:13`). Registering a fake file instead did not help, for the same reason. In a real Quickshell (a throwaway shell with this branch at `design/`, offscreen) `Theme.slate` reads `SystemTheme.dark`, and all 50 primitives compile.
