# Decision log

The decision log of HyprAero's frames module. Newest last. One line per decision: date, decision, reason. Read the relevant entries (grep for the topic) before changing a rule, and append new ones here.

- 2026-10-25 - Window frames are a HyprAero module of their own: the `frames` branch, started without history, with the `design` branch as a submodule at `design/`. Identifiers: app id `app.hyprAero.frames`, plugin and hyprctl command `hypraero-frames`. Reason: owner's request and choice of name; like every module it must install and run by itself.
- 2026-10-25 - The frames are drawn by a Hyprland plugin in C++ (`IHyprWindowDecoration`), with a Quickshell companion for the window menu, the tooltips and the theme. Reason: owner's choice after the options were laid out: only code inside the compositor can stack a frame between overlapping windows and move it with its window in the same frame; a layer surface drawn by Quickshell sits above or below every window and trails behind moves. QML draws menus and tooltips better and has the design's primitives.
- 2026-10-25 - C++ follows the kit's new C++ section (`.aero/CODE_STYLE.md` section 5, the `design` branch's `DECISIONS.md`, same day), checked by `.clang-format` and `.clang-tidy`; C++26 with GCC, CMake + Ninja, Hyprland's headers through `pkg-config`. Reason: owner's confirmation that the TypeScript rules apply as far as C++ allows; Hyprland's plugin interface passes C++ objects, so the plugin is built as Hyprland is.
- 2026-10-25 - Safety before features (AGENTS.md section 5.1): every entry point guarded and `noexcept`, a safety switch that turns the plugin off for the session at the first unexpected error, weak references to Hyprland's objects only, no function hooks, no threads, nothing blocking, every outside value untrusted, a complete unload. Reason: owner's rule: the plugin runs inside Hyprland, a crash ends the whole session, so doing less but safely is preferred over reaching pretty frames at any cost.
- 2026-10-25 - `pluginInit` refuses a load by throwing (another Hyprland build, loaded twice), the one place our code throws. Reason: it is Hyprland's interface for refusing; Hyprland 0.56.2 catches it ("crashed in init. Unloading.", in its binary's strings) and does not call `pluginExit`.
- 2026-10-25 - Tests are plain C++ executables with one small header of checks, built with AddressSanitizer and UndefinedBehaviorSanitizer; the plugin itself is built without them. Reason: no test library to depend on; sanitizers find the memory errors that would crash Hyprland, but cannot run in a library loaded into a Hyprland built without them.
- 2026-10-25 - No Minimize button. Reason: owner's decision: Hyprland has no minimized windows, so it would mean nothing for now; the owner has an idea for later.
- 2026-10-25 - The plugin is tried in a second Hyprland nested in a window of the owner's session, with the owner's permission each time, never in the owner's running Hyprland. Reason: a broken plugin would end the owner's session; a Hyprland without any screen cannot start (tried with no Wayland display and no DRM device: `CBackend::create() failed!`), so the nested one, which opens a window, is the only separate one.
- 2026-10-25 - The skeleton's plugin draws nothing: it loads, checks the version and answers `hyprctl hypraero-frames`. Reason: the frame's looks need measuring and the way tokens reach the plugin needs deciding first (AGENTS.md section 8); a test frame drawn from made-up values would break the token rule for nothing.
