# Decision log

The decision log of HyprAero's design branch. Newest last. One line per decision: date, decision, reason. Read the relevant entries (grep for the topic) before changing a rule, and append new ones here. Decisions from before this branch existed are in the `bar` branch's `DECISIONS.md`.

- 2026-10-24 - HyprAero is one repository with a branch per module (`bar`, `notifications`, ...) and a landing page on `main`; the design (tokens, primitives, theme follower) and the Aero kit are the `design` branch, included in each module branch as a git submodule at `design/` (`branch = design`). It was cut out of the bar's history with `git subtree split --prefix=design`, so its files keep their history. Reason: owner's request: a module installs and runs on its own (`git clone -b <module> --recurse-submodules`) without the other modules' code or resources, the repository stays one, and the design is never copied. The rules every module shares (repository layout, Windows' assets, glass, identifiers) moved into this `AGENTS.md`, which each module's `CLAUDE.md` loads.
- 2026-10-24 - Files here import only Qt, Quickshell and this folder. `SystemTheme.qml` and `colorScheme.js` moved here from the bar's `services/`; `iconColor.js` moved here whole (only `IconColorReader` used it); the analog clock's `handAngles` moved out of the bar's `calendar.js` into `clockHands.js`, and the avatar's `initial` and `avatarIndex` out of the bar's `userInfo.js` into `avatar.js`, each with its tests. Reason: the branch must load in any module, which has no `services/` of the bar; the calendar and the user's folders stay the bar's logic.
- 2026-10-24 - `DragSource` is not part of the design; it goes back to the bar. Reason: it reads the bar's `Apps`, `Workspaces`, `Tray` and `BarDrag`. It came here on 2026-10-11 only to keep the bar and the start menu from importing each other, which a neutral folder in the bar also does.
- 2026-10-24 - `WindowsIcon` keeps reading `../resources/icons/`, which inside a module is the module's own folder. Reason: each module ships only the Windows icons it uses.
- 2026-10-24 - QML tests stand in for Quickshell's `Singleton` (now holding children), `Process` and `SplitParser`, and register the real `SystemTheme.qml` as a singleton in the fake `qs.design` qmldir. Reason: `Theme.qml` finds `SystemTheme` through its own folder, and Qt treats a `pragma Singleton` file found that way as a plain type unless a qmldir registered that file as a singleton (import trace: `TYPE/URL`; every test warned `Unable to assign [undefined] to bool` at `Theme.qml:13`). Registering a fake file instead did not help, for the same reason. In a real Quickshell (a throwaway shell with this branch at `design/`, offscreen) `Theme.slate` reads `SystemTheme.dark`, and all 50 primitives compile.
- 2026-10-24 - `Balloon` is Windows 7's notification balloon, drawn from the tooltip's tokens (`tooltip-face`, `tooltip-border`, `menu-shadow`), `radius-panel` corners and `text` words; only its stem has tokens of its own (`balloon-stem-width`, `-height`, `-inset`, added to `.aero/STYLE.md` "Notification balloons"). Reason: Windows draws its balloons with the tooltip class of its theme, so the same values are reused rather than copied. No picture of a Windows 7 balloon or its theme file (`aero.msstyles`) is among the owner's references, so its sizes (12px words, 16px stem, 300px wrap) and the title's colour come from memory of Windows 7: to be checked against a screenshot.
- 2026-10-24 - The balloon's outline is an SVG path from `balloonShape.js` (node-tested), drawn by a `Shape` with a `MultiEffect` shadow under it; the outline draws over the effect again. Reason: a `RectangularShadow` cannot follow the stem, and without a GPU (Qt's software renderer leaves effects out) the outline alone still shows.
- 2026-10-24 - `Balloon` shows the 16px icon and a picture together (the picture 48px, left of the title and the words), draws `GenericAppIcon` when asked (`genericIcon`) or when the icon fails to load, and wraps its action buttons onto more rows (`Flow`). Reason: owner's request: see both the app's icon and the picture sent with the notification, and as many actions as the app gives, as in the old AGS shell (16px icon, 64px picture); Windows 7 had one or the other, at 32px. One row of buttons ran out of the balloon past two or three actions.
- 2026-10-25 - Window frames' tokens (`.aero/STYLE.md` "Window frames", `Theme.qml` `frame*`): the frame's sizes, its glass tint and lines for the active and inactive window, the lines around the window, the title's colour and whether it glows; inactive and Slate values estimated, not measured. And an exception to "none of it is shipped": the frames module ships the pieces of Windows 7's own frame atlas. Reason: the frames module (`frames` branch) draws Windows 7's frame; the owner chose Windows' own pictures for "exactly the same design", as a module ships Windows' own icons (`AGENTS.md` section 4.3). No primitive changed; no module has to change anything.
- 2026-10-26 - Window frames lose the title's glow (`frame-title-glow` removed from `.aero/STYLE.md` and `Theme.qml`); the title is centred in the caption's height. Reason: owner's request: the glow showed as a light grey smudge behind the title on Aero, and the title sat low in the caption. Only the frames module used the token (`git grep frameTitleGlow` on every branch); it drops it in the same change.
- 2026-10-28 - A taskbar button whose app asks for attention flashes as Windows 7's: `TaskbarButton.attention`, the open face turning orange (`taskbar-item-face-attention`) and back every `taskbar-item-flash-interval` (530ms, Windows' default caret blink rate, which its flashing follows), `attentionFlashes` times (0: for as long as it asks), then orange until it stops asking; `flash()` starts over for a new request (`taskbarFlash.js`). The orange is measured on Windows 7's "Flash Button" state of its taskbar button picture (aero.msstyles, image 1014, as a Seven Forums tutorial shows it, flattened, so alpha estimated); Slate's is estimated; the fades are `motion-fast`. Reason: owner's request for Windows 7's "app attention" in the bar. An addition only: no module has to change anything.
- 2026-10-28 - The start orb's mark glows as a blurred copy of itself in its own colours (`orb-mark-glow` is now only its opacity, 0.65) instead of a one-colour `MultiEffect` shadow. Reason: owner's report: at rest the mark's bottom looked blurred and doubled; the teal shadow ringed the mark's blue bottom, a second blurred mark (seen in offscreen renders at the owner's 1.725 pixel ratio). Only `StartOrb` used the token (`git grep orbMarkGlow` on every branch); no module has to change anything.
- 2026-10-28 - The start orb's mark can wear Windows 7's flag (`HyprlandMark.colors: 'windows'`, `StartOrb.markColors`; tokens `orb-flag-red` / `-green` / `-blue` / `-yellow`, drawn from values, estimated by eye) and, in either colours, be split into the flag's four panes by gaps as wide as the opening at the mark's top (27.2 of the path's 312.92 units; `gaps`, `markGaps`). The orb's bottom light is dimmer (`orb-body` from `#46c2ff` to `#2a8fd0`). Reason: owner's request: a Windows-coloured mark to choose, with or without the flag's gaps, and the bright bottom light hid the mark's bottom, being of nearly its colour. Additions only, `StartOrb` and `HyprlandMark` default to the old look; the bottom light changes for every module.
- 2026-10-28 - The start orb's mark is drawn bolder: its outline stroked in its own colours `orb-mark-weight` wide (12 of the path's 312.92 units, Qt's `ShapePath.strokeGradient`; `HyprlandMark.weight`, 0 by default), the gaps narrowing with its opening, and the item a `margin` bigger on every side, since a layer over it (the orb's glow and brightness) draws only what is inside it: the weight was cut off along the bowl. Reason: owner's request: the mark was too thin on the orb, the flag's colours most of all. 8, 12 and 16 were rendered; 16 nearly closes the opening at the top.
- 2026-10-28 - `StartOrb.logo`: a picture (a vector one, drawn at the screen's pixels) the module gives in place of the mark, with the mark's glow and brightness; `.aero/STYLE.md` "Start orb" allows Windows 7's flag there. Reason: owner's request for Windows 7's flag in the bar's orb; the picture stays the module's, as Windows' icons do (`AGENTS.md` section 4.3). An addition: no module has to change anything.
- 2026-10-28 - `StartOrb` centres a `logo` as it is (the module centres its picture's frame on what it shows), without the drop's nudge down; a logo is drawn 0.635 of the orb wide. Reason: the bar's Windows 7 flag sat a pixel or two to the bottom-left; the bar's copy of it now has a frame centred on the flag (bar `DECISIONS.md`).
