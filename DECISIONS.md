# Decision log

The decision log of HyprAero's frames module. Newest last. One line per decision: date, decision, reason. Read the relevant entries (grep for the topic) before changing a rule, and append new ones here.

- 2026-10-25 - Window frames are a HyprAero module of their own: the `frames` branch, started without history, with the `design` branch as a submodule at `design/`. Identifiers: app id `app.hyprAero.frames`, plugin and hyprctl command `hypraero-frames`. Reason: owner's request and choice of name; like every module it must install and run by itself.
- 2026-10-25 - The frames are drawn by a Hyprland plugin in C++ (`IHyprWindowDecoration`), with a Quickshell companion for the window menu, the tooltips and the theme. Reason: owner's choice after the options were laid out: only code inside the compositor can stack a frame between overlapping windows and move it with its window in the same frame; a layer surface drawn by Quickshell sits above or below every window and trails behind moves. QML draws menus and tooltips better and has the design's primitives.
- 2026-10-25 - C++ follows the kit's new C++ section (`.aero/CODE_STYLE.md` section 5, the `design` branch's `DECISIONS.md`, same day), checked by `.clang-format` and `.clang-tidy`; C++26 with GCC, CMake + Ninja, Hyprland's headers through `pkg-config`. Reason: owner's confirmation that the TypeScript rules apply as far as C++ allows; Hyprland's plugin interface passes C++ objects, so the plugin is built as Hyprland is.
- 2026-10-25 - Safety before features (AGENTS.md section 5.1): every entry point guarded and `noexcept`, a safety switch that turns the plugin off for the session at the first unexpected error, weak references to Hyprland's objects only, no function hooks, no threads, nothing blocking, every outside value untrusted, a complete unload. Reason: owner's rule: the plugin runs inside Hyprland, a crash ends the whole session, so doing less but safely is preferred over reaching pretty frames at any cost.
- 2026-10-25 - `pluginInit` refuses a load by throwing (another Hyprland build, loaded twice), the one place our code throws. Reason: it is Hyprland's interface for refusing; Hyprland 0.56.2 catches it ("crashed in init. Unloading.", in its binary's strings) and does not call `pluginExit`.
- 2026-10-25 - Tests are plain C++ executables with one small header of checks, built with AddressSanitizer and UndefinedBehaviorSanitizer; the plugin itself is built without them. Reason: no test library to depend on; sanitizers find the memory errors that would crash Hyprland, but cannot run in a library loaded into a Hyprland built without them.
- 2026-10-25 - No Minimize button. Reason: owner's decision: Hyprland has no minimized windows, so it would mean nothing for now; the owner has an idea for later.
- 2026-10-25 - The plugin is tried in a second Hyprland nested in a window of the owner's session, with the owner's permission each time, never in the owner's running Hyprland. Reason: a broken plugin would end the owner's session; a Hyprland without any screen cannot start (tried with no Wayland display and no DRM device: `CBackend::create() failed!`), so the nested one, which opens a window, is the only separate one.
- 2026-10-25 - The skeleton's plugin draws nothing: it loads, checks the version and answers `hyprctl hypraero-frames`. Reason: the frame's looks need measuring and the way tokens reach the plugin needs deciding first (AGENTS.md section 8); a test frame drawn from made-up values would break the token rule for nothing.
- 2026-10-25 - The frame's pictures (caption buttons, their glows, the title's glow, the glass's streaks) are Windows 7's own, cut pixel for pixel from its DWM atlas by `tools/cut-pictures.py` and embedded in the plugin with `#embed`; the glass, its lines and the title are drawn from tokens. Reason: owner's choice ("exactly the same design"); the atlas is Windows' own drawing, and `design/AGENTS.md` section 4.3 puts Windows' originals before imitations. It is an exception to `.aero/STYLE.md`'s "none of it is shipped", written there.
- 2026-10-25 - The frame's tokens reach the plugin as a header generated at build time from `design/Theme.qml` (`plugin/tools/tokens.cmake`, both themes); the companion only says which theme. A missing token stops the build. Reason: owner's choice; the values are typed once, in the design, and the plugin draws correctly without the companion.
- 2026-10-25 - The companion sends each app's icon (16 and 32 pixels, as the icon theme draws them at those sizes) through the hyprctl command; the plugin shows Windows 7's generic application icon until then. Reason: owner's choice; the plugin may not read files inside Hyprland's calls (AGENTS.md section 5.1), and the icon theme's lookup already exists in QML.
- 2026-10-25 - The door's requests carry classes and pixels in hexadecimal (interface version 1, `core/command.hpp`). Reason: hyprctl hands the plugin one line split at spaces; hexadecimal keeps any class (spaces, slashes, invalid UTF-8) and any pixel data one plain word, and is trivial to check.
- 2026-10-25 - The plugin is linked with `-z nodelete` and counts its loads; a frame from an earlier load does nothing. Reason: Hyprland deletes a hidden window's decoration only when the window is shown again, possibly after the plugin was unloaded; without it that delete would call into unmapped code and crash Hyprland. Cost: a rebuilt plugin loaded again under the same path runs the old code until Hyprland restarts.
- 2026-10-25 - The build refuses any compiler but GCC. Reason: Hyprland is built with GCC and its plugin interface passes C++ objects; an editor's CMake integration had configured `build/` with clang without a word.
- 2026-10-25 - The inactive glass and the Slate frame's colours are estimated (paler and more see-through for inactive; Slate darkened like the rest of Slate), not measured. Reason: the references show only active Aero frames; to be measured when the owner has pictures (AGENTS.md section 8).
- 2026-10-25 - The glass's streaks are laid at 1:1 from the window's top-left corner, not from the screen's. Reason: compared on Windows 7 screenshots the window-anchored fit was only slightly better (correlation 0.61 against 0.53), so this is a weak choice, easy to change.
- 2026-10-25 - The title's glow reaches 13px past the words on each side, 33px tall, centred on the caption band; Aero only. Reason: measured on Windows 7 screenshots; Slate's white title on dark glass needs no glow.
- 2026-10-25 - The buttons' glows are cut off at the frame's outer edge. Reason: a decoration draws only inside its own box; drawing outside would need a second decoration for little.
- 2026-10-25 - The companion copies the bar's icon lookup (`companion/AppIcons.qml`). Reason: modules share no code but the design's; a candidate to move into the `design` branch if a third module needs it.
- 2026-10-25 - The companion reads an icon's pixels in a see-through, input-less background layer window (`hypraero-frames-icons`) that exists only while it reads, through `Canvas.loadImage(url, size)`, unloading the previous picture first. Reason: a canvas paints only inside a window; and a canvas keeps a picture by its address alone, so the 32 pixel read was the 16 pixel picture scaled up (seen in the separate Hyprland), and drawing an `Image` item gave nothing on the first read.
- 2026-10-25 - First version without tooltips, moving by the title, double click and the window menu. Reason: owner asked for the simplest version first: frame, icon, title and buttons.
